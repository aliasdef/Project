# Реальный пример атаки Man-in-the-Middle через ARP-spoofing в Kali Linux

Привет всем! В этой мини-лабе я захотел посмотреть, как работает `arpspoof` на реальном примере. 

Для этого нам понадобится средство гипервизора (Oracle VirtualBox, VMware) и две виртуальные машины.

### Настройки сети
В настройках сетевых адаптеров обеих машин необходимо выставить режим **«Сетевой мост» (Bridged Adapter)**. Это нужно для того, чтобы машины находились в одном сегменте локальной сети (в моем случае — `192.168.1.x`).

**Стенд для лабораторной работы:**
* **Атакующий (Kali Linux):** `192.168.1.7`
* **Жертва (Ubuntu):** `192.168.1.9`
* **Шлюз (Router / Gateway):** `192.168.1.1`

## Шаг 1. Разведка и подготовка

Запускаем Kali Linux и проверяем, видит ли наша Kali тачку с Ubuntu:
```bash
ping 192.168.1.9
```

Также нам необходимо узнать точное имя нашего сетевого интерфейса на Kali:
```bash
ip a
```
*(Ищем название интерфейса, например `eth0` или `wlan0`).*

Если пинги идут и интерфейс найден, значит, мы можем переходить к следующему шагу — запуску перехвата трафика.

---

## Шаг 2. Запуск ARP-спуфинга

Для этого нам понадобится утилита `arpspoof`, которая по умолчанию входит в состав пакета `dsniff` в Kali Linux.

В первом окне терминала запускаем атаку на жертву:
```bash
sudo arpspoof -i INTERFACE_NAME -t 192.168.1.9 192.168.1.1
```

**Пояснение по флагам команды:**
* `-i INTERFACE_NAME` — указывает сетевой интерфейс Kali (например, `eth0`), через который отправляются пакеты.
* `-t 192.168.1.9` — цель атаки (Target). Мы отправляем пакеты на IP-адрес жертвы.
* `192.168.1.1` — хост, под который мы маскируемся. Мы говорим машине Ubuntu, что MAC-адрес роутера — это наш MAC-адрес.

Если вы увидите бесконечные строки с отправкой пакетов, всё прошло успешно!

*[ТУТ СКРИН ИЗ ТЕРМИНАЛА 1]*

Но атака односторонняя. Нам нужно, чтобы роутер тоже думал, что мы сидим на айпишнике `192.168.1.9`, и слал пакеты от интернета нам назад. Что ж, приступим! Открываем второе окно терминала:

```bash
sudo arpspoof -i INTERFACE_NAME -t 192.168.1.1 192.168.1.9
```

**Пояснение по флагам команды:**
* Здесь цели меняются местами: флаг `-t 192.168.1.1` указывает, что мы атакуем роутер, а финальный IP `192.168.1.9` заставляет роутер поверить, что под IP-адресом Ubuntu скрывается наша машина Kali.

---

## Шаг 3. Решение проблемы с пропаданием интернета

**Проблема, с которой я столкнулся:** после запуска двустороннего спуфинга на машине Ubuntu полностью отваливался интернет (пакеты доходили до Kali, но она их просто сбрасывала).

Чтобы Kali начала работать как роутер и пропускала трафик сквозь себя, нужно выполнить следующие действия в третьем окне терминала:

1. Включаем пересылку пакетов на уровне ядра Linux:
   ```bash
   sudo sysctl -w net.ipv4.ip_forward=1
   ```
2. Проверяем, что режим пересылки успешно активировался (команда должна вернуть `1`):
   ```bash
   cat /proc/sys/net/ipv4/ip_forward
   ```
3. Разрешаем пересылку пакетов на уровне встроенного файрвола Kali:
   ```bash
   sudo iptables -P FORWARD ACCEPT
   ```
4. Включаем маскирацию трафика (NAT), чтобы роутер корректно возвращал ответы:
   ```bash
   sudo iptables -t nat -A POSTROUTING -o INTERFACE_NAME -j MASQUERADE
   ```
5. Очищаем таблицы от старых блокирующих правил:
   ```bash
   sudo iptables -F
   ```

---

## Шаг 4. Итоговая проверка и перехват

Теперь заново запускаем спуфинг в первых двух терминалах и проверяем доступ к интернету на машине жертвы (Ubuntu):
```bash
ping 8.8.8.8
```

Если пинг идет стабильно, значит сеть восстановлена и весь трафик скрытно течет через нас! Самое время запустить `Wireshark` для перехвата данных:

```bash
sudo wireshark
```

В фильтре Wireshark пишем `ip.addr == 192.168.1.9` и анализируем пакеты. Лаба успешно завершена!
